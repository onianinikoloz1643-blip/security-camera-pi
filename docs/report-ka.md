## 1. შესავალი და პროექტის ზოგადი აღწერა

ჭკვიანი (edge-ai) კამერა არის უსაფრთხოების კამერის სისტემა, რომელიც Raspberry Pi 5-ზე რეალურ დროში ამოიცნობს ადამიანებსა და ტრანსპორტს. ხელოვნური ინტელექტის მთელი დამუშავება ხდება თავად მოწყობილობაზე (edge): კადრის აღება, ობიექტების ამოცნობა, ჩაწერა, შეტყობინება და ვებ-ინტერფეისი — ყველაფერი ლოკალურად მუშაობს, ღრუბლოვანი სერვისის, ანგარიშისა და გამოწერის გარეშე.

როდესაც სისტემა აღმოაჩენს ადამიანს ან ტრანსპორტს, ის ინახავს ანოტირებულ snapshot-ს, იწერს ვიდეო კლიპს, რეალურ დროში აახლებს ვებ-დაშბორდს და აგზავნის Telegram შეტყობინებას ფოტოთი. დეტექციამდე მსუბუქი motion filter ამოწმებს არის თუ არა მოძრაობა, რათა ნეირონული ქსელი მხოლოდ მაშინ გაეშვას, როცა სცენაში რეალურად რაღაც იცვლება.

### ძირითადი ფუნქციები
- ადამიანებისა და ტრანსპორტის (car, motorcycle, bus, truck, bicycle) რეალურ დროში ამოცნობა TensorFlow Lite მოდელით.
- motion filter, რომელიც დეტექციას ტოვებს სტატიკურ კადრებზე და ზოგავს CPU-ს.
- event-based ჩაწერა: თითო გამოჩენაზე ერთი snapshot და ერთი ვიდეო კლიპი, რომელიც გრძელდება სანამ მოძრაობა არ შეწყდება.
- ჩანაწერების ავტომატური კონვერტაცია MP4-ში (ffmpeg), რათა დაიკრას ბრაუზერსა და Telegram-ში.
- ლოკალური ვებ-დაშბორდი HTTPS-ით, რეალურ დროში განახლებებით (Server-Sent Events), snapshot-ის გადიდებით (zoom/pan) და ვიდეო ფლეიერით.
- Telegram შეტყობინებები ფოტოთი და ინტერაქტიული ბოტი ბრძანებებით.
- დისკის ავტომატური მართვა — ძველი ფაილების წაშლა, როცა დისკი 90%-ს გადააჭარბებს.
- systemd სერვისი, რომელიც ავტომატურად ეშვება ჩატვირთვისას და აღდგება ავარიის შემდეგ.

## 2. პრობლემის აღწერა და მიზნები

ბაზარზე არსებული უსაფრთხოების კამერების უმეტესობა დამოკიდებულია ღრუბლოვან სერვისზე: ვიდეო და დეტექციები იგზავნება მწარმოებლის სერვერებზე, ფუნქციები ხშირად გამოწერის უკან არის, ხოლო მომხმარებელს მცირე კონტროლი აქვს იმაზე, თუ სად ინახება მისი ვიდეო. ეს ქმნის კონფიდენციალურობისა და ხარჯების პრობლემას.

პროექტის მიზანია შეიქმნას უსაფრთხოების კამერა, რომელიც იმავე ძირითად ამოცანას ასრულებს — ამოიცნობს ადამიანებსა და ტრანსპორტს და აფრთხილებს მფლობელს — მაგრამ ამას აკეთებს მთლიანად ლოკალურად, ხელმისაწვდომ single-board hardware-ზე, ღრუბლის გარეშე.

### მოქმედების არეალი
- შედის: რეალურ დროში დეტექცია, motion filter, event-based snapshot და ვიდეო ჩაწერა, ვებ-დაშბორდი, Telegram შეტყობინებები და ბოტი, დისკის მართვა, HTTPS და ავტენტიფიკაცია.
- არ შედის: სახის ამოცნობა (face recognition), ნომრის ამოცნობა (license plate), მრავალკამერიანი მხარდაჭერა, ღრუბლოვანი შენახვა და მობილური აპლიკაცია.

## 3. სისტემის არქიტექტურა და დიზაინი

სისტემა არის ერთი Python აპლიკაცია (main.py), რომელიც კოორდინაციას უწევს რამდენიმე მოდულს, პლუს Flask ვებ-სერვერი, რომელიც ფონურ thread-ში მუშაობს. ყოველი მოდული ერთ კონკრეტულ ფუნქციაზე აგებს პასუხს.

main.py-ის ციკლი ყოველ კადრზე ასრულებს pipeline-ს: კადრის აღება → motion filter → დეტექცია → event (snapshot + კლიპი + შეტყობინება) → შენახვა.

### კომპონენტების დიაგრამა
```
კამერა (IMX708)
 -> main.py  (capture -> motion -> detection -> event)
      -> motion.py        (pixel-diff motion filter)
      -> detector.py      (EfficientDet-Lite0 INT8, LiteRT)
      -> storage.py       (snapshots / recordings / logs, MP4 კონვერტაცია)
      -> telegram_notify  (შეტყობინება ფოტოთი)
 -> web.py  (Flask HTTPS + SSE)   -> ბრაუზერი / ტელეფონი (LAN)
 -> telegram_bot.py  (long-poll)  -> Telegram Bot API  -> ტელეფონი
```

### დეტექციის თანმიმდევრობა
1. main.py იღებს კადრს კამერიდან (1280×720).
2. motion.py ადარებს კადრს წინა კადრს; თუ მოძრაობა არ არის, კადარი დეტექციამდე გამოტოვებულია.
3. თუ მოძრაობაა, detector.py უშვებს EfficientDet-Lite0-ს და ტოვებს მხოლოდ უსაფრთხოების კლასებს threshold-ის (0.40) ზემოთ.
4. label დადასტურებულად ითვლება, თუ ის ორ ზედიზედ კადარში ჩანს (consecutive-frames filter), რაც ხსნის ცალკეული კადრის false positive-ებს.
5. პირველ დადასტურებულ დეტექციაზე ინახება ერთი snapshot, იგზავნება Telegram alert და იწყება ჩაწერა.
6. ჩაწერა გრძელდება სანამ სცენაში მოძრაობაა და ჩერდება მაშინ, როცა მოძრაობა cooldown-ის განმავლობაში აღარ ფიქსირდება.

### დიზაინის გადაწყვეტილებები
- მცირე, კვანტიზებული მოდელი (INT8) შერჩეულია სიჩქარისთვის — Pi-ის CPU-ზე სწრაფად მუშაობს accelerator-ის გარეშე.
- motion filter დეტექციამდე ამცირებს CPU-ის დატვირთვასა და სითბოს, რადგან სტატიკურ სცენაზე ნეირონული ქსელი საერთოდ არ ეშვება.
- consecutive-frames filter ამცირებს false positive-ებს.
- ჩაწერა მიბმულია მოძრაობაზე და არა მხოლოდ დეტექციაზე, ასე კლიპი გრძელდება სანამ ობიექტი მოძრაობს.
- AVI-ში ჩაწერა საიმედოა OpenCV-ით; შემდეგ ფონური ffmpeg კონვერტაცია MP4-ში იძლევა ბრაუზერსა და Telegram-ში დაკვრის საშუალებას.

## 5. მონაცემთა შენახვა და ფაილური სტრუქტურა

აპლიკაცია არ იყენებს SQL მონაცემთა ბაზას — მონაცემები ინახება ფაილურ სისტემაში, თავად Raspberry Pi-ზე. ეს შეესაბამება პროექტის „ლოკალური, ღრუბლის გარეშე" პრინციპს.

| ადგილი | დანიშნულება | შიგთავსი |
|---|---|---|
| snapshots/ | ანოტირებული სურათები | YYYYMMDD_HHMMSS_label.jpg |
| recordings/ | ვიდეო კლიპები | YYYYMMDD_HHMMSS_recording.mp4 |
| logs/ | სისტემის ლოგები | system.log (rotating, 5 MB × 3) |
| auth.txt | ვებ-ავტენტიფიკაცია | username:sha256(password) |
| ssl/ | HTTPS სერტიფიკატი | cert.pem, key.pem |
| models/ | მოდელი და labels | detect.tflite, labelmap.txt |

### ლოგიკა
- snapshot და მისი ვიდეო კლიპი ერთ timestamp-ს იზიარებენ, რითაც ვებ-ინტერფეისი კლიპს უსაბამებს თავის thumbnail-ს.
- ერთ event-ზე ინახება ერთი snapshot (გამოჩენის დასაწყისში).
- ჩაწერა იყოფა ცალკეულ ფაილებად ყოველ 5 წუთში (MAX_RECORDING_SECONDS).
- დისკის გამოყენების 90%-ზე ძველი ფაილები იშლება, სანამ არ ჩამოვა 85%-მდე; მიმდინარე ჩანაწერი არასოდეს იშლება.

## 6. API და ინტერფეისების დოკუმენტაცია

ვებ-სერვერი მუშაობს HTTPS-ზე, 8080 პორტზე, და ყველა endpoint მოითხოვს HTTP basic auth-ს.

### HTTP endpoints
| მეთოდი | Endpoint | აღწერა | პასუხი |
|---|---|---|---|
| GET | / | დაშბორდი (HTML) | text/html |
| GET | /stream | რეალურ დროში მოვლენების ნაკადი (SSE) | text/event-stream |
| GET | /api/status | სისტემის სტატისტიკა | JSON |
| GET | /api/recordings | ჩანაწერები thumbnail-ებით | JSON |
| GET | /snapshots/&lt;file&gt; | snapshot-ის ჩვენება | image/jpeg |
| GET | /recordings/&lt;file&gt; | ვიდეოს დაკვრა/ჩამოტვირთვა | video/mp4 |

GET /api/status აბრუნებს:
```json
{ "snapshots": 12, "recordings": 4, "disk_used_gb": 13.4, "disk_total_gb": 56.5, "disk_percent": 23.7 }
```

### SSE მოვლენები (/stream)
| მოვლენა | data | მნიშვნელობა |
|---|---|---|
| detection | {"labels": ["person"]} | კადარში დადასტურდა მითითებული კლასი |
| snapshot | {"filename": "...", "total": N} | შეინახა ახალი snapshot |
| recording_start | {} | დაიწყო ჩაწერა |
| recording_stop | {"total": N} | დასრულდა ჩაწერა |
| disk | {"percent": 23.7} | დისკის გამოყენების განახლება |

### Telegram ბოტის ბრძანებები
| ბრძანება | მოქმედება |
|---|---|
| /status | uptime, რაოდენობები, დისკი, ჩაწერის სტატუსი |
| /snapshot | ბოლო snapshot |
| /video | ბოლო ჩანაწერი (snapshot-თან ერთად) |
| /disk | დისკის გამოყენება |
| /stop | დეტექციის შეჩერება |
| /start | დეტექციის განახლება |
| /password &lt;ახალი&gt; | ვებ-პაროლის შეცვლა |
| /help | ბრძანებების სია |

## 7. ინსტალაცია და კონფიგურაცია

გამოცდილია Raspberry Pi OS 64-bit (Bookworm)-ზე, Raspberry Pi 5-ზე.

```bash
git clone https://github.com/onianinikoloz1643-blip/security-camera-pi.git ~/security_camera
cd ~/security_camera
python3 -m venv --system-site-packages venv
source venv/bin/activate
sudo apt install -y python3-picamera2 python3-opencv ffmpeg
pip install ai-edge-litert flask numpy requests
mkdir -p models
wget -O models/detect.tflite \
  https://storage.googleapis.com/mediapipe-tasks/object_detector/efficientdet_lite0_uint8.tflite
mkdir -p ssl
openssl req -x509 -newkey rsa:4096 -nodes -days 365 \
  -keyout ssl/key.pem -out ssl/cert.pem -subj "/CN=raspberrypi.local"
python main.py
```

კამერის ჩასართავად `/boot/firmware/config.txt`-ში: `camera_auto_detect=0` და `dtoverlay=imx708`.

ძირითადი პარამეტრები `config.py`-ში: `DETECTION_THRESHOLD` (0.4), `CONSECUTIVE_FRAMES_REQUIRED` (2), `RECORDING_COOLDOWN` (10წმ), `STORAGE_MAX_PERCENT` (90), `FPS` (10), `CAMERA_HFLIP`/`CAMERA_VFLIP`. Telegram-ის token და chat id იკითხება environment variable-ებიდან, რათა საიდუმლო არ მოხვდეს რეპოზიტორში.

## 8. მომხმარებლის სახელმძღვანელო და Use Cases

- მომხმარებელი ხსნის `https://raspberrypi.local:8080`-ს და შედის admin-ით (პაროლი იქმნება პირველ გაშვებაზე და იბეჭდება კონსოლში).
- დაშბორდზე ჩანს სტატუსი (snapshot/ჩანაწერების რაოდენობა, დისკი), ბოლო snapshot-ები და ჩანაწერები thumbnail-ით.
- როცა ადამიანი შემოდის კადარში: ჩნდება toast შეტყობინება, რეალურ დროში ემატება ახალი snapshot, ჩნდება ჩანაწერის ბარათი და მოდის Telegram alert.
- snapshot-ზე დაჭერით ის იხსნება სრულ ეკრანზე — scroll-ით zoom, drag-ით გადაადგილება.
- ჩანაწერი იკვრება პირდაპირ გვერდზე (play/pause, 10წმ-ით წინ/უკან, seek, fullscreen).
- Telegram-ში: /status სტატუსისთვის, /snapshot ბოლო სურათისთვის, /video ბოლო ვიდეოსთვის, /stop და /start დეტექციის სამართავად.

## 9. ტესტირება და ხარისხის უზრუნველყოფა

- ინსტალაციის შემოწმება: `verify_install.py` უშვებს 36-პუნქტიან შემოწმებას (გარემო, ფაილები, მოდელი, სერტიფიკატი, კამერა, სერვისი). სამიზნე Pi-ზე გადის 36/36.
- hardware-ის გარეშე ტესტირება: `test_system.py` უშვებს მთლიან pipeline-ს `mock_camera.py`-ით (სტატიკური სურათი), რაც საშუალებას იძლევა ვებ-ინტერფეისისა და დეტექციის ლოგიკის ტესტირება Pi-ის გარეშე.
- გაშვებისას config-ის ვალიდაცია: `validate_config()` უარს ამბობს გაშვებაზე არასწორი პარამეტრით ან აკლია ფაილით (მოდელი, სერტიფიკატი).
- წარმადობის გაზომვა: `benchmark.py` ზომავს inference-ის, motion filter-ისა და სისტემის მაჩვენებლებს.
- manual QA: ხელით შემოწმდა დეტექცია, ჩაწერა, ვებ-დაშბორდი და Telegram-ის ყველა ბრძანება.

## 10. განთავსება/დეპლოიმენტი

სისტემა მუშაობს როგორც systemd სერვისი თავად Raspberry Pi-ზე — და არა ღრუბელში. სერვისი ავტომატურად ეშვება ჩატვირთვისას და `Restart=always`-ით აღდგება ავარიის შემდეგ.

| კომპონენტი | როლი |
|---|---|
| systemd service | ავტო-გაშვება და აღდგენა |
| Python venv | აპლიკაციის გარემო |
| IMX708 camera | ვიდეო წყარო |
| microSD | snapshots / recordings / logs |
| Telegram Bot API | გარე შეტყობინების არხი |

შენიშვნა: სისტემა განკუთვნილია ლოკალური ქსელისთვის (LAN), self-signed სერტიფიკატის უკან, და არ არის გათვლილი ინტერნეტში პირდაპირ გამოსატანად.

## 11. უსაფრთხოება და კონფიდენციალურობა

- ვებ-ინტერფეისი მუშაობს HTTPS-ზე (self-signed certificate).
- ყველა endpoint დაცულია HTTP basic auth-ით; პაროლი ინახება SHA-256 hash-ად `auth.txt`-ში (0600 უფლებებით), შედარება — მუდმივ დროში (constant-time).
- პირველ გაშვებაზე იქმნება ძლიერი შემთხვევითი პაროლი; პაროლის შეცვლისას მოწმდება სიძლიერე.
- Telegram-ის token და chat id იკითხება environment variable-ებიდან და არასოდეს ხვდება რეპოზიტორში.
- ბოტი პასუხობს მხოლოდ მითითებულ chat id-ს.
- მთელი დამუშავება და შენახვა ლოკალურია — ვიდეო არ იგზავნება ღრუბელში (Telegram არის არჩევითი გარე არხი).

## 13. დასკვნა და რეპოზიტორის მითითება

პროექტი აღწევს დასახულ მიზნებს: Raspberry Pi 5 კამერით რეალურ დროში ამოიცნობს ადამიანებსა და ტრანსპორტს, იწერს და აცნობებს მოვლენებს, და იმართება ვებ-დაშბორდითა და Telegram ბოტით — მთლიანად მოწყობილობაზე, ღრუბლის გარეშე. motion pre-filter და მცირე კვანტიზებული მოდელი მას საკმარისად სწრაფსა და გრილს ხდის უწყვეტი მუშაობისთვის.

### წარმადობა (გაზომილი Raspberry Pi 5-ზე)
| მაჩვენებელი | შედეგი |
|---|---|
| inference | 42.7 ms (23.4 FPS) |
| motion filter | 5.3 ms (~190 FPS) |
| CPU ტემპერატურა დატვირთვისას | 58.7 °C |
| RAM | 588 MB / 8 GB |

10 FPS-იანი capture-ის პირობებში ~23 FPS inference იძლევა საკმარის მარაგს, ხოლო Pi რჩება thermal throttle-ის ზღვარს (~80 °C) ქვემოთ.
